Box Relay · contract review

Harnesses decide, sandboxes do the work, Box carries the files

The Extractor and the Contract reviewer are inner harnesses: model loops that decide what to do next. Each controls its own Linux sandbox, and its Box Mount syncs only that agent's own Box folder, so the contract PDF never reaches the Reviewer. The outer harness is the coordinator, a scripted workflow with no model and no Box Mount. Through the Box API it pins every file version, hands the exact extraction to the Reviewer, and checks after each step that nothing changed. If something did, it stops and asks a person. Every harness runs on Temporal, so every wait, approval and crash is durable.

The run, about 90 seconds plus your clicks

  1. Type go. The coordinator asks Box for the contract's and playbook's current versions and pins them: file ID, version and SHA-1. A new Work/HALVORSEN-MSA/<run>/ folder means runs never collide. outer harness · Box API

  2. Extractor, an inner harness. Waits until the pinned contract version has synced into its own sandbox, reads it, writes extraction.json. The coordinator waits until Box holds exactly what the Extractor wrote, and pins that too. sandbox-extractor

  3. Check. The coordinator asks Box whether any pinned file has a new version. If someone changed one, it stops and asks you: continue with the new version (redoing what depends on it) or stop. It waits as long as it takes. outer harness · you

  4. Supplier check and spend, in code. A fixed activity reads the supplier out of the pinned extraction inside the Extractor's sandbox; only that fact reaches the coordinator. It checks the ERP and sanctions lists (retrying through an outage, just flaky on) and reads 12 months of spend from Databricks. outer harness

  5. Handoff in Box. The coordinator copies that exact extraction version from Extraction/ into Review/ on the Box side, and the Reviewer's Box Mount syncs it down. The PDF never moves. Box API · Box Mount

  6. Contract reviewer, an inner harness. Waits for the copied version, compares every clause with the playbook, and writes review_memo.md and review_findings.json. Another check follows. sandbox-reviewer

  7. A person approves. The card lists every version checked. Approve copies the memo version you saw to Reviewed/ and records the findings in Databricks; an edit made after the card appeared isn't published. you

Add-ons

Change a file mid-run

While the Extractor works, save a new version of the contract or playbook in Box. After the step, the coordinator stops with a card naming the file, both versions and who changed it. Approve to continue with the new version, reject to stop.

A · a person edits in Box

Type re-review, then edit the playbook in the Box web app, for example to allow Net 15 for Halvorsen. The coordinator sees the new version in Box and pins it, it syncs into the Reviewer's sandbox, and the Reviewer writes review_memo_v2.md with payment terms now OK.

B · crash and resume

Run just crash reviewer during a review. It kills the worker mid model call. The sandbox restarts it and, about 6 seconds later, Temporal retries the same call on the new worker. The memo lands once, with no duplicate writes.

Ask anything

After a run, ask a question such as "what did the review find on liability?" A model answers, reading each file in the sandbox that holds it.

Harness outside, sandbox inside

A harness decides; its sandbox does the work. Each sandbox has its own disk, and the Python a model writes runs there. The harness's state lives in Temporal, so losing a sandbox loses no progress.

Least privilege

Each agent sees only its own folder. The Extractor has the PDF; the Reviewer has the playbook and a copy of the extraction. The coordinator holds no files at all, only versions and hashes.

Governed in Box

No Box credentials in agent code. The mounts authenticate for the agents; the coordinator uses the Box API. Box permissions, version history and the web app stay the source of truth for people.

Durable by default

A changed file, a person's answer or a restarted worker is just a step. Temporal records each check and each wait, so the coordinator picks up exactly where it was.

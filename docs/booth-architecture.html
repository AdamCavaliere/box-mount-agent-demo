Booth demo · Box Relay · contract review

Harnesses decide, sandboxes do the work, Box carries the files

The Extractor and the Contract reviewer are inner harnesses: model loops that decide what to do next. Each one controls its own Linux sandbox, where the work runs, and the two never talk to each other. They hand work over only through a Box folder that Box Mount syncs into each sandbox. The outer harness is a scripted relay workflow with no model. It starts the inner harnesses and runs the case. Every harness runs on Temporal, so every wait, approval and crash is durable.

The run, about 60 seconds plus your click

  1. Type go. The outer harness (the relay workflow) fingerprints the contract and playbook as its sandbox sees them. A new Work/HALVORSEN-MSA/<run>/ folder means runs never collide. outer harness

  2. Extractor, an inner harness. Waits until that exact contract version has synced into its own sandbox, reads it, writes extraction.json. Box Mount uploads it to Box. sandbox-booth-extractor

  3. Handoff through Box. The reviewer's sandbox downloads extraction.json a few seconds later. The ticker shows it crossing. The outer harness passes only the fingerprint, so the reviewer waits for that version, never a stale one. Box Mount

  4. Contract reviewer, an inner harness. Compares every clause with the playbook and writes review_memo.md back to Box. sandbox-booth-reviewer

  5. A person approves. The chat links the memo in Box, and an approval card holds the publish step. Approve copies it to Reviewed/; reject leaves it in Work/. The workflow can wait here as long as it takes. you

Two add-ons

A · a person edits in Box

Type re-review, then edit the playbook in the Box web app, for example to allow Net 15 for Halvorsen. The edit syncs into every sandbox within seconds, and the reviewer writes review_memo_v2.md with payment terms now OK. No agent was told about the change; it read Box.

B · crash and resume

Run just crash booth-reviewer during a review. It kills the worker mid model call. The sandbox restarts it and, about 6 seconds later, Temporal retries the same call on the new worker. The memo lands once, with no duplicate writes.

Ask anything

After a run, ask a question such as "what did the review find on liability?" A model answers by reading the contract, playbook and memo from Box.

Harness outside, sandbox inside

A harness decides; its sandbox does the work. Each sandbox has its own disk and Box Mount, and the Python a model writes runs there. The harness's state lives in Temporal, so losing a sandbox loses no progress.

Least privilege

An agent sees /box, never a Box folder ID. It can't reach anything outside Booth/, and each agent may write only its own output file.

Governed in Box

No Box credentials in agent code. The mount authenticates. Box permissions, version history and the web app stay the source of truth for people.

Durable by default

Waiting for a sync, a person or a restarted worker is just a step. Temporal records each one, so the outer harness picks up exactly where it was.

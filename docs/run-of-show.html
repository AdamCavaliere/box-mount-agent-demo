Temporal Agent Kit × Box Mount

Box Relay Run of Show

Two AI agents, each in its own Linux sandbox with its own Box folder, hand a contract review to each other through Box. A coordinator with no model pins every file version, checks between steps that nothing changed, and asks a person when something did. Temporal makes every handoff, wait and crash durable. This page covers start-up, what each piece does, and how to run the demo.

What each piece does

PieceRuns whereWhat it does
Temporal dev serveryour Mac · :7233, UI :8233Records every step of every agent, so work survives crashes and waits. The Temporal UI shows each agent's history and status line.
Session-manager workeryour MacRuns the Agent Kit's session-manager workflow, which keeps the list of chat sessions and starts new ones.
Agent Kit UI serveryour Mac · :8000The UI where you type and approve. It offers one agent: Box Relay.
sandbox-coordinatorDockerThe coordinator: a scripted workflow (no AI model). It runs the two agents in order, pins each file version through the Box API, checks between steps that none changed, runs the supplier check and the Databricks steps, and asks a person to approve publishing. No Box Mount: it never holds file content.
sandbox-extractorDockerAI agent 1. Its Box Mount syncs only Extraction/. Reads the contract PDF and writes extraction.json: every clause verbatim plus the key terms.
sandbox-reviewerDockerAI agent 2. Its Box Mount syncs only Review/, so it never sees the PDF. Reviews the contract from the copied extraction.json against the playbook and writes review_memo.md and review_findings.json.
Box foldersBoxExtraction/ (contract, extraction), Review/ (playbook, copied extraction, memo, findings), Reviewed/ (approved memos). The coordinator copies the exact extraction version from one agent's folder to the other's.
Ticker (just ticker)a terminalOne line per file crossing between sandboxes, including the coordinator's Box API copies, with how long Box took.

Before the event day before or morning of

  1. Docker Desktop running, Box and OpenAI keys in place

    secrets/box-jwt-config.json, .env (Box folder IDs) and .env.local (OpenAI key) are already set up. Make sure you're signed in to Box in the browser you'll present from. First time ever: run just setup.

  2. Start the stack (next section), then reset the folders

    just reset

    About a minute. Clears old runs and published memos and restores the contract and playbook. Never delete files in the Box folders by hand while the sandboxes run (a Box Mount bug can strand later files).

  3. Do one full rehearsal run

    Run the core demo and the add-ons once, end to end, on the network you'll present on.

Start-up

One command

~90 s to ready
just launch
Opens one Ghostty window with six titled tabs (Temporal, Session manager, Sandboxes, Agent Kit UI, Ticker, Crash), starts each in the right order, and opens the Agent Kit UI, Temporal UI, Box folder and, last, the architecture diagram in your browser once every worker is polling. just launch dry opens the tabs but only prints the commands. The first run asks macOS for permission to control Ghostty: allow it.

The demo

Open the Agent Kit UI, click New session and choose Box Relay. The UI doesn't start a session on its own.

Open with one line

10 s
Say"Two AI agents, each in its own sandbox with its own Box folder. They never talk to each other. A coordinator written in code, with no model, hands files between them through Box and checks every version. Temporal makes all of it durable, and a person approves what goes out."

Run it

~90 s
DoType go and press Enter. They seeThe Extractor reads the contract in its sandbox. In the ticker: ↑ sandbox-extractor uploaded Extraction/…/extraction.json, then ⇢ sandbox-coordinator COPY … -> Review/…/extraction.json, then ↓ sandbox-reviewer downloaded Review/…. The supplier check (ERP and sanctions) and spend lookup run in between. The Reviewer writes its memo. Say"The Reviewer's sandbox never gets the PDF, and the coordinator never gets any file at all. It sees versions and hashes through the Box API, and copied that exact version of the extraction across, on the Box side." OptionalRun just flaky on first: the ERP lookup times out twice and the Temporal UI shows the retries.

Human in the loop: approve publishing

~20 s
They seeThe chat says Review ready for approval with a link to the memo in Box, and a publish_memo_to_reviewed_folder card that lists every version checked. DoClick the link to show the memo in Box. Then show the Temporal tab: the coordinator's status line says it's waiting for a person. Say"Nothing is running while it waits. It could wait an hour or survive a restart. And what gets published is exactly the version I'm looking at." DoClick Approve. The memo appears in Reviewed/ and the chat links it. (Reject leaves it in the Reviewer's Work/.)

A file changes mid-run

Add-on~30 s
DoType go. While the Extractor works, edit Review/Playbook/playbook.md in Box (or upload a new version of the contract in Extraction/Incoming/). They seeAfter the step, a continue_with_changed_file card: the file, both versions, who changed it, and what continuing would redo. Say"Between every step the coordinator asks Box whether anything it relies on changed. When something did, it doesn't guess. It stops and asks, and Temporal holds the run until someone answers."

People edit in Box

Add-on A~45 s
DoAfter a run, type re-review. The status line says it's waiting for an edit to the playbook in Box. DoIn Box, open Review/Playbook/playbook.md and change the payment-terms row to Net 45; Net 15 is approved for Halvorsen | Shorter than Net 15. They seeThe coordinator pins the new version, the ticker shows it reaching the Reviewer's sandbox, and the Reviewer writes review_memo_v2.md, now marking payment terms OK. The approval card returns. Say"People and agents work in the same Box files. Legal changed a rule in Box; the agent picked up that exact version."

Crash and resume

Add-on B+6 s
DoType go, then in Terminal 3 (or the Crash tab) run just crash reviewer. It waits for the Reviewer's model call, then kills the worker with kill -9. They seekilled …@sandbox-reviewer (kill -9) during invoke_model_activity…. The sandbox restarts the worker in a second; about 6 s later the Temporal UI shows the same model call running again as attempt 2 under a new worker PID. The memo still lands once. Say"The process died mid-thought. Temporal resumed the exact step, and nothing it had already written to Box was redone."

Between runs

  • Type go again in the same session: every run gets its own Work/HALVORSEN-MSA/<run>/ folder, so nothing collides.
  • If you edited the playbook, run just playbook-reset (a few seconds) to put the original back. Box keeps the edited one in version history.
  • Sessions close themselves after 10 minutes with no messages. A closed session says so; click New session.

If something goes wrong

SymptomFix
worker=DOWN in just statusTemporal isn't running or just restarted: check Terminal 1. Workers reconnect on their own within seconds.
"No worker available" when starting a sessionThe workers aren't polling yet. Wait for just status to show worker=up three times, then click New session.
UI shows an error or can't create a sessionRestart just server (Ctrl-C, run again).
Approval card doesn't appearReload the page; the workflow is still waiting.
Nothing in the tickerRestart just ticker; check just status.
"This agent is closed"It idled out. Click New session.
Folders getting long, or a run looks stuck on syncjust reset (~1 min) between sessions.

Don'tterminate session-manager in the Temporal UI (it ends every session), and don't delete files in the Box folders while the sandboxes run.

Shut down

One command ends every workflow, stops Temporal, the session manager, the UI, the ticker and the sandboxes, and closes the Ghostty window:

just stop

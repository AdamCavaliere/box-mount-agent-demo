Booth demo · Temporal Agent Harness × Box Mount

Box Relay Booth Run of Show

Two AI agents, each in its own Linux sandbox, hand a contract review to each other through a Box folder. Temporal makes every handoff, wait and crash durable, and a person approves what gets published. This page covers start-up, what each piece does, and how to run the demo.

What each piece does

PieceRuns whereWhat it does
Temporal dev serveryour Mac · :7233, UI :8233Records every step of every agent, so work survives crashes and waits. The Temporal UI shows each agent's history and status line.
Session-manager workeryour MacRuns the Harness's session-manager workflows, which keep the list of chat sessions and start new ones.
Booth UI serveryour Mac · :8000The Agent Harness UI where you type and approve. It offers only Box Relay and uses its own booth-session-manager.
sandbox-booth-coordinatorDockerThe relay: a scripted workflow (no AI model) that runs the two agents in order, passes file fingerprints, and asks a person to approve publishing.
sandbox-booth-extractorDockerAI agent 1. Reads the contract PDF from its Box Mount and writes extraction.json back to Box: every clause verbatim plus the key terms (payment days, renewal, liability caps, indemnity, termination, insurance, governing law).
sandbox-booth-reviewerDockerAI agent 2. Never sees the PDF. Waits for extraction.json to arrive through Box, reviews the contract from it against the playbook, and writes review_memo.md.
Box Mount (in each sandbox)DockerKeeps the Booth/ folder synced both ways with Box. It is the only thing the sandboxes share. Agents never see Box credentials.
Box folder Booth/BoxIncoming/ contract, Playbook/playbook.md rules, Work/ agent output per run, Reviewed/ approved memos.
Ticker (just ticker)a terminalOne line per file crossing between sandboxes, with how long Box took.

Before the event day before or morning of

  1. Docker Desktop running, Box and OpenAI keys in place

    secrets/box-jwt-config.json, .env (Box folder IDs) and .env.local (OpenAI key) are already set up. Make sure you're signed in to Box in the browser you'll present from.

  2. Start the stack (next section), then reset the booth folder

    just booth-reset

    About a minute. Clears old runs and published memos and restores the original playbook. Never delete files in the Box folder by hand while sandboxes run (a Box Mount bug can strand later files).

  3. Do one full rehearsal run

    Run the core demo and both add-ons once, end to end, on the booth network.

Start-up in order, one terminal each

One command

~45 s to ready
just booth-launch
Opens one Ghostty window with five titled tabs (Temporal, Session manager, Sandboxes, Booth UI, Ticker), starts each in the right order, and opens the Harness UI, Temporal UI and Box folder in your browser once the UI is up. The steps below are what it runs, if you'd rather start them by hand. just booth-launch dry opens the tabs but only prints the commands. The first run asks macOS for permission to control Ghostty: allow it.

The demo

Open the Harness UI: it starts a Box Relay session for you. If it says the agent is closed, click New session and choose Box Relay.

Open with one line

10 s
Say"Two AI agents, each in its own sandbox. They share nothing except a Box folder that Box Mount syncs into each one. Temporal makes the handoffs between them durable, and a person approves what goes out."

Run the relay

~45 s
DoType go and press Enter. They seeThe Extractor card appears and reads the contract from its Box Mount. In the ticker: ↑ sandbox-booth-extractor uploaded …/extraction.json, then ↓ sandbox-booth-reviewer downloaded … +3 s via Box. The file appears in Box. The Reviewer card starts, and review_memo.md goes up the same way. Say"The reviewer never sees the PDF. It works only from what the first agent wrote to Box. Its first step, wait_for_file_to_sync_from_box, waits for that exact version to arrive in its own sandbox; if Box were slow, Temporal would keep retrying that step, durably." OptionalIn the Temporal tab, open reviewer-subagent-…: the history reads wait_for_file_to_sync_from_box → read_handed_off_file_from_box → vfs.box-mount.read (playbook) → get_approved_clause_language → vfs.box-mount.write. No PDF read anywhere.

Human in the loop: approve publishing

~20 s
They seeThe chat says Review ready for approval with an Open review_memo.md in Box link, and a publish_memo_to_reviewed_folder approval card. DoClick the link: show the memo in Box (risk score, findings table, redlines). Then show the Temporal tab: the relay's status line says it's waiting for a person. Say"Nothing is running while it waits. It could wait an hour or survive a restart. The agents did the work; a person decides what reaches Legal." DoClick Approve. Within ~10 s the memo appears in Booth/Reviewed/ and the chat links the published copy. (Reject leaves it in Work/.)

People edit in Box

Add-on A~45 s
DoType re-review. The relay waits; its status line says "waiting for someone to edit Playbook/playbook.md in Box". DoIn Box, open Booth/Playbook/. Either edit playbook.md (payment-terms row: Net 45; Net 15 is approved for Halvorsen | Shorter than Net 15), or use the file's menu → Upload New Version and pick ~/box-mount-agent-demo/booth/playbook.md, which already has that change. Rehearse whichever you'll use. They seeThe ticker shows playbook.md landing in every sandbox ("from Box, edited outside these sandboxes"). The Reviewer writes review_memo_v2.md, now marking payment terms OK, and the approval card returns. Say"People and agents work in the same Box files. Legal changed a rule in Box; the agent picked up that exact version."

Crash and resume

Add-on B+6 s
DoType go, then right away in Terminal 3 run just crash booth-reviewer. It waits for the Reviewer's model call, then kills the worker process with kill -9. They seekilled …@sandbox-booth-reviewer (kill -9) during invoke_model_activity…. The sandbox restarts the worker in a second; about 6 s later the Temporal UI shows the same model call running again as attempt 2 under a new worker PID. The memo still lands once. Say"The process died mid-thought. Temporal resumed the exact step, and nothing it had already written to Box was redone."

Between visitors

  • Type go again in the same session: every run gets its own Work/HALVORSEN-MSA/<run>/ folder, so nothing collides.
  • If you did add-on A, run just booth-playbook-reset (a few seconds) to put the original playbook back. Box keeps the edited one in version history.
  • Sessions close themselves after 10 minutes with no messages. A closed session says so; click New session.

If something goes wrong

SymptomFix
worker=DOWN in just statusTemporal isn't running or just restarted: check Terminal 1. Workers reconnect on their own within seconds.
UI shows an error or can't create a sessionRestart just booth-server (Ctrl-C, run again). It recreates its session-manager if needed.
Approval card doesn't appearReload the page. The UI updates in 5-second steps in this mode; the workflow is still waiting.
Nothing in the tickerRestart just ticker; check just status.
"This agent is closed"It idled out. Click New session.
Folder getting long, or a run looks stuck on syncjust booth-reset (~1 min) between sessions.

Don'tterminate booth-session-manager in the Temporal UI (it ends every session), and don't delete files in the Box folder while the sandboxes run.

Shut down

One command stops Temporal, the session manager, the booth UI, the ticker and the sandboxes (the Ghostty tabs stay open at a prompt):

just booth-stop
